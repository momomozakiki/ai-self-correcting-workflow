# 2026-W35  (2026-08-24 – 2026-08-30)

## 2026-08-29

### [design] `plans/golden-rules-migration.md` – staged replacement of `.ai/`
- **What:** Recorded the plan to replace the `.ai/` governance library with three tiers —
  golden-rule markdown checklists per domain, one executing agent per domain, and an
  orchestrator that finds, authors or improves the rules. Split into eight stages (0–7) with a
  validation gate between each, three of which are declared stopping points where the repo is
  coherent and shippable. Stage 1 is the uncontested cleanup on its own; every later stage is
  optional. Branch `feat/golden-rules` cut from `feat/governance-v14-integration`, **not**
  `main` — `main` is 25 commits behind and contains no `.ai/`, no `.claude/agents/`, no
  `.claude/skills/` and only one of the four test files, so a main-based branch would have had
  nothing to migrate.
- **Why:** Three independent reviews were run before committing to the rewrite. The
  design-soundness review found that the first draft's self-improving loop rebuilt a mechanism
  this repo had already tried and dropped — `docs/checklist-system.md` §6 records *confidence
  self-adjustment* as dropped because "the agent that applied a rule would also decide its own
  false-positive rate… No ground truth anywhere in the loop." The draft rebuilt exactly that
  and rewrote rule *text* rather than a score. It also had the strike criterion inverted
  ("struck if it fired with nothing behind it" deletes the rules that work, since a rule that
  prevents failures produces no failures), and deleted `.ai/03-planning/` — the only artifact
  in the repo that reviews a plan — from a system made entirely of plans. The blast-radius
  review found the migration is larger and quieter than assumed: `.ai/` regrows itself from
  three `mkdir(parents=True)` calls in the hook, `run_self_test` prints
  `[ ok ] checklist sources validated` over an empty directory, `test_hook.py:1427` builds its
  corpus by rglobbing `.ai/` and so would pass vacuously, and `SettingsWiring` — the only proof
  a `PreToolUse` hook is registered in both settings files — lives inside the file being
  deleted. All four corrections are carried into the plan.
- **Provenance:** Subagent model mechanics verified against
  `code.claude.com/docs/en/sub-agents.md` (resolution order: `CLAUDE_CODE_SUBAGENT_MODEL` →
  dispatch-time `model` parameter → frontmatter → main conversation; omitted `model:` means
  `inherit`; nesting to depth 3; hooks and CLAUDE.md inherited by subagents). Frontmatter field
  names cross-checked against this repo's own
  `.claude/skills/claude-code-layout/references/frontmatter-by-type.md`, which confirms
  `effort` (`low`…`max`) and camelCase `disallowedTools` for subagents.

### [config] `.claude/agents/stage-gate-auditor.md` – read-only gate certifier
- **What:** New subagent, mirrored byte-identically to `templates/agents/`. `model: opus`,
  `effort: high`, `disallowedTools: Write, Edit, NotebookEdit` — it runs the suite and the
  self-test but cannot change what it judges. Reports **pass / fail / cannot verify** per gate
  criterion with the raw output behind each verdict, and closes with a single
  `PROCEED` / `DO NOT PROCEED` line. Its body names the six failure modes it must actively
  suspect: the vacuous pass over an empty directory, `--self-test` exiting 0 on
  `validation skipped`, a silently shrinking test count, directories that regrow via
  `mkdir(parents=True)`, instruction files pointing at deleted paths (which produce no error at
  all), and unmirrored `.claude/**` edits.
- **Why:** Every gate in the staged plan would otherwise be certified by the same agent that
  did the work — the "no ground truth in the loop" flaw the design review caught, reapplied to
  the implementation process. The auditor is a cheap second opinion, not an authority; the
  go/no-go decision stays with the user.
- **Verification:** Gate 0 requires the auditor to have returned a real failure before it is
  trusted. Deliberate drift was appended to `templates/agents/layout-auditor.md` and the suite
  correctly failed `TemplateMirrors.test_mirrors_exist_and_match` with a byte-level diff naming
  the file; drift then reverted and the suite returned to 251 green. **The auditor itself could
  not be dispatched** — Claude Code scans `.claude/agents/` at session start, so a subagent
  written mid-session is not discoverable until the session restarts. Gate 0 is therefore
  **partially verified**: the broken state is provably detectable, but the auditor's own
  reporting is unexercised and remains an open item before Stage 1 is certified.
- **Baseline:** 251 tests pass at stage 0.

### [design] `golden-rules/` – seeded from two incidents, not from speculation
- **What:** Opened the golden-rules library early, out of stage order, with `README.md` (the
  two-layer contract, the two `Status:` forms, and the sourcing rule) plus two domain files:
  `git/existing-project.md` and `claude-code/configuration.md`. Both are seeded from failures
  that occurred **during this session**, each recorded as a dated incident in the `Sources:`
  line of the group it produced. New group in the git rules — *"Before cutting a branch —
  verify the base, don't assume it"* — with the concrete command
  (`git ls-tree -d --name-only <base> -- <path>`) and the re-cut procedure. New group in the
  Claude Code rules — *"Before depending on what you just created"* — stating that a subagent
  written mid-session is undiscoverable until restart and that `/reload-skills` covers skills,
  not subagents.
- **Why:** The plan had these files written speculatively at stage 2, which the plan itself
  flags as the weak path: `.ai/GROWTH.md` — *"a rule that nobody hit yet is a guess; a rule
  harvested from a real mistake is knowledge."* Two real mistakes arrived before stage 2 did,
  so the library is seeded with knowledge rather than guesses. This is the intended growth
  mechanism running for the first time, and it ran on the author's own errors.
- **Incident 1 (base not verified):** A branch was cut from `main` for a migration whose every
  target file existed only on `feat/governance-v14-integration`, 25 commits ahead — no `.ai/`,
  no `.claude/agents/`, no `.claude/skills/`, one of four test files, and `hooks/`/`skills/`
  still at the repo root. Caught on the first `cat` of a file the plan named, before anything
  was written; branch re-cut from the correct base. Nothing verified that the base contained
  the subject of the work.
- **Incident 2 (artifact not exercised):** `stage-gate-auditor` was written, correctly placed,
  correctly mirrored and green across all 251 tests, then failed to dispatch —
  `Agent type 'stage-gate-auditor' not found`. The agent whose whole purpose is to
  independently certify later stages could not itself be certified, and the gap surfaced only
  at the moment of use.
- **Provenance:** Authority citations are version-pinned per the README's own rule — Pro Git,
  2nd ed. (Chacon & Straub, 2014); Conventional Commits 1.0.0; GitHub Flow (retrieved
  2026-08-29); Claude Code sub-agents docs (retrieved 2026-08-29). Items with neither an
  authority nor an incident are labelled `reasoned from first principles` rather than given a
  citation they do not have.
- **Also observed:** running the test suite rewrites `.ai/00-system/maturity-tracker.json` on
  every invocation — reproduced three times, reverted each time to keep the diff clean. This is
  the self-modifying-artifact behaviour stage 1 removes.

### [test] Gate 0 closed — the auditor was made to fail before it was trusted
- **What:** Dispatched `stage-gate-auditor` against Gate 1 with the deliberately false claim
  that Stage 1 was complete, over a tree carrying injected mirror drift. It checked
  independently, **refused the claim**, and returned `fail` on all four criteria with the raw
  command output behind each. It also caught the unreverted drift artifact, flagged that the
  `golden-rules/` commit was Stage 2 work landing while Stage 1 was untouched, and ran its
  destructive experiments in a scratchpad copy rather than the working tree.
- **Correction it made to the plan:** line 56 claimed `test_hook.py:1427` gives a plain green
  no-op on an empty corpus. Only half true — `test_every_tripwire_actually_trips` does, but
  `test_declared_mode_matches_what_the_guard_returns` carries a count assertion that fires
  (`0 != 4`). The plan is amended; that class has partial protection worth preserving in
  whatever replaces it, and *that* is the recorded reason for its stage-3 deletion.
- **Why it matters:** an auditor that has never returned a failure has not been tested. This
  one now has, against a false claim rather than a cooperative one.

### [code] Stage 1 — safety net added, distribution machinery removed
- **What (item 1, archive):** `.ai/` and `templates/ai-library/` copied verbatim to
  `plans/archive/2026-08-29_ai-library-retirement/` (58 files each, counts verified equal)
  with a README stating what the archive is *for* — raw material for the golden-rules domains
  that replace it, not sentiment.
- **What (item 2, port):** `SettingsWiring`'s four portable tests moved from
  `test_governance_library.py` to `test_claude_layout.py`, plus a new corpus guard. This is the
  only proof a `PreToolUse` hook is registered in **both** settings files; it was living inside
  the module stage 3 deletes. The fifth test (artifacts citing settings must cite the class)
  did not move — it is genuinely about library artifacts and retires with them. Dangling
  docstring at `test_claude_layout.py:156` repointed.
- **What (item 3, corpus guards):** New `CorpusNotEmpty` classes in `test_claude_layout.py` and
  `test_skills.py`, plus an inline guard in `test_hook.TestEnforcementModeMatchesGuard.setUp`.
- **What (items 4–5, deletion and false-pass fixes):** `templates/ai-library/` deleted (58
  files). Maturity ladder, tracker write and `DEFAULT_MATURITY_TRACKER` removed from
  `workflow_hook.py`; `governance.maturity_tracker` removed from `schemas/config_schema.json`
  and both configs in the same commit; `maturity-tracker.json` and its manifest entry deleted
  (`total_items` 6 → 5). `TemplateParity` removed with the reason recorded in place.
  `test_writes_maturity_tracker` **inverted** into
  `test_self_test_does_not_write_to_the_repository`, which compares the file tree before and
  after; `test_low_maturity_still_passes` became `test_a_bare_project_still_passes`.
- **Why the maturity ladder went:** it rewrote a *tracked* file on every `--self-test`, so
  merely running the suite dirtied the working tree — reverted by hand three times in one
  session before it was named. An instrument that mutates what it measures is not one. The
  level was also "reported, never enforced": a number nothing consumed, which reads as a score,
  and a score invites optimising the score.
- **Why the false pass went:** with `.ai/` deleted the self-test still printed
  `[ ok ] checklist sources validated within 180d` and exited 0. The branch could not
  distinguish "all clear" from "no corpus". Now counts what it examined, reports
  `(88 items)` on success and `[warn] no checklist items found` on an empty one.
- **Scoping decision, taken and flagged:** item 4 also called for stripping `confidence_level`,
  `risk_source` and `risk_weight` from the rule JSONs. Not done — those 58 files are deleted
  wholesale in stage 3, so the edit evaporates. Only the parts that outlive stage 3 were done:
  the hook, the schema, the configs, and the template mirror. The fields sit inert until then.
- **Verification:** 251 → **259 tests, all green** (the suite grew, as it must). Each new guard
  proven to fire by emptying its directory in an isolated scratchpad copy — including the
  decisive case where `.claude/agents/` **and** `templates/agents/` are both empty:
  `TemplateMirrors` reports `OK` comparing nothing to nothing, while `CorpusNotEmpty` fails.
  That is the vacuous-pass class demonstrated and closed. `--self-test` shows
  `[ ok ] config valid against schemas/config_schema.json`; running it plus the full suite
  produces **zero** change in `git status`.
