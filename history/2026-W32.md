## 2026-08-04

### [code] `main_branch` auto-detection in the Stop hook
- **What:** Closed the "Harden the hook dispatcher" roadmap item. Added
  `detect_main_branch()` + `resolve_main_branch()` to `hooks/workflow_hook.py` and
  wired the latter into `handle_stop()`, replacing the flat
  `stop_hook.main_branch` lookup that defaulted to `"main"`. Resolution order:
  explicit non-empty `stop_hook.main_branch` → `git symbolic-ref --short
  refs/remotes/<remote>/HEAD` (local ref, no network) → optional `git remote show
  <remote>` `HEAD branch:` parse → `"main"`. Three new config keys
  (`main_branch_autodetect` default true, `main_branch_remote` default `origin`,
  `main_branch_probe_remote` default false) in `schemas/config_schema.json`,
  `.claude/workflow_config.json`, and `templates/workflow_config.json`; the two
  configs now omit `main_branch` so autodetect is the dogfooded path. Resolution
  runs *after* the `stop_hook_active`/block-cap short-circuit and memoises into a
  new `main_branch_detected` state key (persisted even on a non-blocking Stop), so
  a session shells out to git at most once. 11 new tests in
  `TestMainBranchDetection` (precedence, blank-value fall-through, custom remote,
  `(unknown)` HEAD, no-network-by-default, memoisation, and two end-to-end Stop
  cases) — suite 27 → 38, all green.
- **Why:** The hardcoded `main` default mis-fires on every repo whose default
  branch is `master`/`trunk`/`develop`: a dirty tree on the real default branch
  looked like a missed Phase-3 closure and produced a spurious commit reminder on
  every close. The roadmap named `git remote show origin`, but that contacts the
  remote — unacceptable as the primary probe inside `Stop`, which runs while the
  user waits for the session to close. The local `refs/remotes/*/HEAD` ref carries
  the same answer for free (written by `git clone`), so it became step 2 and the
  network probe became opt-in. Explicit pins keep winning, so every existing
  adopter config is unaffected.
