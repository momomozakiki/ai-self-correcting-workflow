# 2026-W36  (2026-08-31 – 2026-09-06)

## 2026-08-31

### [design] A worked checklist now leaves an artifact, and omission became arithmetic
- **What:** Added the report format (`golden-rules/REPORTING.md`), its parser
  (`scripts/checklist_report.py`), a shape test (`tests/test_checklist_reports.py`, 20 tests),
  a closure gate (`scripts/checklist_status.py`) and a growth harvester
  (`scripts/checklist_growth.py`). A worked checklist now leaves
  `plans/<plan>/checklists/<domain>/<file>.md`. Every plan carries one `Checklists:` line —
  `none — <reason>` is a valid, recorded decision.
- **Why:** the execution contract was prose — *"report the answers… an absent answer is the
  finding"* — and **nothing anywhere checked that any answer was ever given**. A skipped item
  and a passed item were indistinguishable, because both looked like silence.
  `ROADMAP.md` had pre-registered the gap and guessed it might be unenforceable via a hook.
  That guess was right: checklist *loading* happens inside model reasoning where no hook runs.
  But the **report** is a file, and a file can be reconciled.
- **The question that started it** was whether one agent should monitor another executing a
  checklist. The literal form is not buildable — subagents "run in their own context and
  return only a summary", so a monitor could only ask the executor about the executor's own
  work, which is the loop `docs/checklist-system.md` records as dropped for having no ground
  truth in it. The goal splits instead: *was every item answered* is arithmetic, *is each
  answer true* is judgement. Only the second needs a model, and spending one on the first then
  trusting it to count is the wrong trade twice over.
- **The report is written before the work and doubles as the to-do list** — every verdict
  `todo`, filled in as the agent goes. Not bookkeeping: a checklist loaded at Phase 1 can fall
  out of context before Phase 2 ends (`PreCompact` is still unwired), and an interrupted
  session leaves its outstanding items named on disk.
- **Two zones, and the split is the whole safety property.** The verdict block carries exactly
  the golden file's items; `## Working notes` below it is the agent's own and is never counted.
  An agent that could add lines to the block deciding whether it is finished could always reach
  "finished" — *"a test that can be satisfied by adjusting the data it measures is not a
  test"*. Enforced by reconciling against the golden file rather than a stored snapshot, so
  there is no baseline that could itself be edited.
- **Risk:** design

### [decision] The correction that reshaped the design: a red suite is not a to-do list
- **What:** The first design rejected `todo` outright, so an outstanding item failed the unit
  suite. Changed to: shape, reconciliation and version-match are unit tests and run always;
  *"everything answered"* is a **closure gate** (`scripts/checklist_status.py`) run at Phase 3
  beside the ledger and archive steps.
- **Why it was wrong twice:** there is no closing event a test can observe, so the rule would
  have rejected `todo` **always** — leaving the suite red for the entire duration of every
  task, which destroys the meaning of a red suite. Worse, it would have created direct pressure
  to fill verdicts early to get back to green. That is *mark-then-do*: fabrication, the one
  failure this layer provably cannot detect. **The design would have rewarded its own blind
  spot.**
- **Proven both ways, end to end:** with a `todo` planted in a live report, the unit suite
  passes (20 tests OK) and the gate exits 1 naming the outstanding item and its line. Getting
  this backwards is what would have made a normal working state look broken.
- **Also dropped during the same review:** prefix-matching report text against golden item text.
  It did not prove what it claimed — copying text proves a file was opened, not read — it was
  fragile enough to invite loosening, and it duplicated the `Status:` match that catches the
  case that mattered. Count, position and `Status:` do the work.
- **Risk:** design

### [design] The reports are the evidence base for improving the checklists
- **What:** `scripts/checklist_growth.py` tallies verdicts across reports and prints strike and
  promotion candidates. Repeated `cannot tell from here` is evidence of **unanswerable**;
  repeated `n/a` means the group's *when* is wrong. Recurring Working-notes steps are the
  depth-growth signal.
- **Why:** `GROWTH.md` has always said an item that never applies is a strike candidate, but
  until reports existed that was somebody's impression. This makes it countable.
- **Three things it deliberately does not do**, each for a recorded reason: it never strikes
  anything, only prints candidates for human ratification, because an agent that both applies a
  rule and decides its fate is the killed loop; it sets **no threshold**, because a number to
  clear is a number to game and the ledger already carries an entry about data nudged to satisfy
  a validator; and it prints reason strings rather than bare tallies, because `n/a` is the
  cheapest verdict to write and "the item is wrong" and "someone was avoiding work" are
  identical in a count. **An item that merely keeps passing is never a candidate** — the
  inverted-strike rule.
- **Current output is honest about being empty:** two reports, 33 items, no candidates, and it
  says so — *"Nothing here says the library is good, only that no item has yet been unanswerable
  or inapplicable twice."*
- **Risk:** design

### [doc] What this does not catch, recorded rather than glossed
- **Fabrication.** Write `pass` on every line without looking and everything goes green. This
  makes *omission* impossible and does nothing about *dishonesty*. `ROADMAP.md` now carries the
  verifier that would address it, with the note that reports are its prerequisite rather than
  the reverse.
- **Avoidance.** The chain rests on a self-declared `Checklists:` line; `none — trivial` passes.
  So it catches a checklist started and not finished, not one never declared.
- **An edited golden base.** The verdict block is validated against the golden file, so editing
  the golden file makes both consistent. Closed only when ratified golden files become Tier-0
  protected paths at stage 7 — inherited, and stated as inherited.
- **A reason that says nothing.** `n/a | … | not applicable` satisfies the requirement; the
  check is on shape, not substance.
- **Where it landed:** `ROADMAP.md` moved from `[ ]` to `[~]` rather than `[x]`, with the
  unclosed half written as the `enforcement_note` the original item asked for.
- **Verification:** 296 tests green (was 276). Closure gate CLOSED, exit 0. Negative controls
  each failed **naming the offending path** and were removed: outstanding `todo` (passes suite,
  fails gate), a line added to the verdict block, a line removed, a large Working-notes section
  which must and does **pass**, unknown verdict, stale `Status:`, missing reason, missing notes
  heading, `Golden:` disagreeing with the path, declared-but-absent report, and a plan with no
  `Checklists:` line. `--self-test` config valid. Both skill edits mirrored byte-identical to
  `templates/skills/` in the same commit.
- **Risk:** accountability
